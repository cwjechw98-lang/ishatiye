# BAR SOCIAL

## Демоверсия на GitHub Pages

Адрес: https://cwjechw98-lang.github.io/ishatiye/

`npm run build:pages` собирает отдельную статическую демоверсию в `pages-site/out`. Публикация запускается автоматически при отправке в ветку `main` через `.github/workflows/pages.yml`.

GitHub Pages не запускает сервер и PostgreSQL: в этой версии профиль, сообщения и действия сохраняются только в браузере посетителя. Данные не передаются другим посетителям. Не вводите конфиденциальные сведения. Исходная серверная версия ниже сохранена отдельно; `npm run build` по-прежнему собирает её.

Живое цифровое пространство одного бара: гости рядом, общение, взаимный интерес и события. Адаптивное web-приложение на русском языке, без обязательной установки.

## Что работает

- Гостевая сессия в HttpOnly cookie, мини-профиль, загрузка и кадрирование фотографии, интересы и режим невидимки.
- Presence «Я здесь»: ручной выход и исключение неактивных гостей из списка через 15 минут. Обновление пространства каждые 8 секунд, когда вкладка активна.
- Поиск гостей по имени, описанию и интересам; фильтры по настроению, возрасту и интересам.
- Общий чат, эмодзи и реакции. Сообщения сохраняются в PostgreSQL.
- Взаимный интерес и личные диалоги. API запрещает личные сообщения без взаимного интереса.
- События, запись и отмена участия. Вместимость проверяется в транзакции с блокировкой записи события.
- QR-приглашение, копирование ссылки и скачивание QR для столов. QR создаётся локально, без передачи ссылки внешним сервисам.
- Блокировка, жалобы и демо-модерация.
- Панель заведения с показателями из базы, созданием событий и закреплёнными объявлениями.

## Стек и запуск

Next.js App Router, React, TypeScript, PostgreSQL, Drizzle ORM, Tailwind CSS, Lucide, QRCode.

Требуется PostgreSQL и переменная `DATABASE_URL`. Настройки подключения находятся в `src/db/index.ts`, схема — в `src/db/schema.ts`.

1. Установить зависимости: `npm install`.
2. Применить схему: `npx drizzle-kit push`.
3. Для разработки: `npm run dev`.
4. Для production: `npm run build`, затем обычный запуск Next.js в вашей инфраструктуре.

Демо-данные создаются идемпотентно при первом обращении. Проверка базы и доступности приложения: `GET /api/health`.

## Проверки

- `npx next typegen`
- `npm exec tsc -- --noEmit --pretty false`
- `npm run build`

Браузерный интеграционный сценарий при работающем приложении:

1. `npx playwright install --with-deps chromium`
2. `npx --yes tsx scripts/smoke-test.ts`

По умолчанию используется `http://localhost:3000`; адрес можно изменить через `TEST_BASE_URL`. Сценарий проверяет профиль, фильтры, чат, взаимный интерес, личные сообщения, события, QR, модерацию и мобильную навигацию. Созданные им тестовые записи удаляются через Drizzle. Снимки сохраняются в `.artifacts/`.

## Границы демонстрации

«Место» — демонстрационное заведение. Стартовые гости, взаимные симпатии между ними и события иллюстрируют один живой вечер; они не подтверждают присутствие реальных людей по указанному адресу. При создании демо-сессии добавляются два входящих интереса, чтобы можно было проверить сценарий взаимности. Автоматических ответов в чатах нет.

Посетитель демо получает роль `demo_host`, чтобы попробовать панель заведения. Эта модель доступа намеренно открыта для демонстрации и **не подходит для реального публичного заведения без изменений**. Перед запуском реального бара нужны отдельная аутентификация владельца, назначение ролей, ограничение доступа к venue, политика хранения данных, согласия, защита от злоупотреблений и работающая команда модерации. Нельзя размещать в демо конфиденциальные сведения.

Фотографии и шрифты находятся локально в `public/`. Атмосферный баннер бара сгенерирован для демо; остальные изображения — Pexels и Unsplash. Платёжные тарифы, push-уведомления и сеть заведений в этот MVP не входят.
